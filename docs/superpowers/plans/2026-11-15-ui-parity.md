# Whole-app UI parity implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax.

**Goal:** Port the OpenDesign "Clinic Application Design" prototype (37 surfaces, 7 roles, v3 P0 packets) into the React app as one parity wave.

**Architecture:** React/TypeScript single app. Port the prototype's Preclinic tokens/components/copy/fixture data, add per-role route guards and nav, keep verified native patient/appointment/photo/stock wiring untouched, and render designed-but-unbacked surfaces over clearly marked Demo/Sample fixtures (authoring minimal fixtures where the prototype has none).

**Tech stack:** React 18, TypeScript, Vite, vitest, Playwright, i18n catalogs.

**Spec:** `docs/superpowers/specs/2026-11-15-ui-parity-design.md` + `docs/superpowers/specs/2026-11-15-ui-parity-gap-audit.md`

## Global constraints

- No backend, endpoint, migration, table, permission, site, or commit changes in this wave.
- Design source (prototype files under the user's OpenDesign project dir) is visual/interaction/copy/fixture authority; port, do not embed its runtime.
- Verified native flows stay byte-compatible: patient directory/profile/create/edit + ack; appointment list/detail/reschedule/check-in + ack; photo save; live stock. Their existing tests must pass unchanged.
- Sample everything is Demo/Sample labeled; never imply a Marley contract; `write.appointment.cancel` and clinical/pharmacy/finance/admin writes stay non-wired.
- Authored fixtures (prototype-unbacked components) **must be supported by Frappe and Marley Healthcare**: field names, DocType/workflow semantics and vocabulary model the installed backend contract (design handoff `clinic-backend-api-contract-spec.md`, installed DocTypes), so future native wiring is a data swap, not a redesign.
- i18n: Thai-first/EN; reuse the 1,070 runtime keys and pre-staged `ops.v3.*`/`lab.*`/`surface.*` catalogs.
- Responsive 390/834/1440 and 44px targets/focus rings per Preclinic spec.

## Review Focus

- Sample data mistaken for real integration → each fixture surface renders its Demo/Sample label; test asserts the label + absent network calls in native mode (task 2).
- Route guard regression locking out DOC/NUR/REC from verified flows → guard-matrix test per designed route × role (task 1).
- Native flow regression → rerun transport + patient/appointment suites after every task's route changes (tasks 1–6 verification steps).
- Deterministic fixtures (relative dates must not drift) → frozen-clock test (task 2).
- Responsive overflow on dense ops tables → responsive test at 390 for each new surface family (tasks 5–6).
